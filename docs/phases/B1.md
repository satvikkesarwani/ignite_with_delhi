## Design direction — non-negotiable, this is what stops it looking AI-generated

An **editorial intelligence terminal**. Warm near-black, ochre accent, data-dense, serif
headings against mono numerals.

Palette is already in `:root` — use the Tailwind tokens, never raw hex, never a default
Tailwind colour. Specifically banned: `blue-600`, `indigo-600`, any purple→blue or
purple→pink gradient, any gradient at all, `rounded-2xl`, drop shadows, emoji as icons,
a centered hero.

- **Left rail** 220px fixed: Database · AI Scout · Intake · Graph. `lucide-react` icons at
  18px with labels. Active item marked by a 2px ochre left border, not a filled pill.
- Content area: 24px gutters, asymmetric. Page title in Fraunces 600 at 24px, with a muted
  one-line description beside it — not stacked and centered.
- Header strip: 4 counters from `/api/crm/stats`, mono numerals at 28px, hairline dividers
  between them, no cards.
- Motion: 120ms ease-out on hover and drawer only. Nothing bounces, nothing pulses.

## Build

### 1. Shell — `frontend/src/crm/CrmLayout.jsx`

Left rail, header strip, content outlet. Route at `/crm`. Leave the existing `App.jsx`
mounted and working at `/`.

A small connection indicator in the rail footer: a 6px dot plus mono text — `LIVE` (sage),
`MOCK` (ochre), `OFFLINE` (clay) — driven by `/api/crm/stats`. During the demo this quietly
tells the judge the data is real.

### 2. Database view — `frontend/src/crm/DatabaseView.jsx`

The master directory, and the first thing a mentor sees. It must feel like a real tool with
real data in it.

- Table from `GET /api/crm/candidates`. Columns: Name + email · College · Personas ·
  Top skills · Hackathons · Wins · Engagement · Last active · Status
- 32px rows, sticky header, hairline borders, zebra at 2% opacity. Mono and right-aligned
  for every numeric column. Names in Plex Sans, IDs in mono at 11px muted.
- Personas as bordered badges, not filled pills. One accent colour per persona family.
- Engagement as a 3px horizontal bar plus the mono number — not a donut, not a gauge.
- Instant client-side search across name/email/college/skill, debounced 150ms.
- Filter row: college, skill, persona, status. Plain bordered selects.
- Sortable columns. Cursor pagination, 50/page, mono "51–100 of 600".
- Row click → drawer. Whole row clickable, with a visible focus ring.
- Empty and loading states: skeleton rows, never a spinner. Error state names the endpoint.

### 3. Profile drawer — `frontend/src/crm/ProfileDrawer.jsx`

Right-side slide-over, 520px, from `GET /api/crm/candidates/:id`. **This is where the
context layer becomes visible — give it the most care.**

Order matters:
1. **Identity** — name, college, grad year, role preference, GitHub/LinkedIn links
2. **Narrative** — the synthesized paragraph. Set it larger (15px, 1.65 line-height) with a
   2px ochre left border. It is the product; let it breathe.
3. **Personas + engagement** — badges, and the score with its four components as small
   labelled bars. Judges ask "why 78?" — the answer must be on screen.
4. **Skills** — sorted by confidence. Confidence as a thin bar. On hover, a tooltip listing
   the evidence sources. Flag `claim_gap` with a `lucide-react` `AlertTriangle` in clay and
   the text *"declared, no supporting evidence"*; flag `hidden_strength` in sage. **Do not
   hide these behind a toggle — they are the most interesting thing in the drawer.**
5. **Trajectory** — `score_series` as a bare inline sparkline (SVG, ~48px tall, ochre, no
   axes, no grid, no library). Direction and status as text beside it. Tech drift as
   `React → LangChain`.
6. **Activity facts** — a compact two-column key/value grid, mono values.
7. **Evidence trail** — a collapsible list of `evidence[]`: claim, source type, source ref,
   observed date. Source type as a mono uppercase tag (`CSV` `GITHUB` `TAVILY` `RESUME`).
   Collapsed by default, but the header shows the count: *"Evidence · 24 claims"*.

Keyboard: `Esc` closes, `j`/`k` move between rows, `Enter` opens. Small touches like this
read as craft in a demo.

## Verify before you finish — required

Use the Playwright MCP: open `http://localhost:5173/crm`, screenshot the table, open a

from 100 other hackathon projects?* If the honest answer is yes, change the layout
