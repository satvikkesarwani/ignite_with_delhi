## The constraint that shapes the whole design

Nemotron takes **~25 seconds** on an LLM call. Some answers are instant (existence checks,
template queries, stored narratives — under a second) and some are not.

So the perceived-speed work is yours, and it matters more than any other polish in this app:

- Show **which path the query took**, live: `TEMPLATE · 0.08s` (sage) vs `AI QUERY · 24.1s`
  (ochre) as a small mono badge. Making the fast path visibly fast is more impressive than
  pretending everything is fast.
- While waiting, show **real progressive stages** from the response's `strategy` field —
  "resolving person" → "querying graph" → "synthesizing". Never a bare spinner, never a
  fake progress bar.
- Stream nothing you have not got. If the API does not stream, do not fake a typing effect.

## Build — `frontend/src/crm/ScoutView.jsx`

Split screen, **58% left / 42% right**, both independently scrollable. Not 50/50 — the
asymmetry is deliberate and reads as designed.

### Right — conversation

- Message list. Organizer messages right-aligned on a bordered surface; agent messages
  left-aligned, full width, no bubble. The agent is writing a briefing, not chatting.
- Under each agent answer: the strategy badge, latency in mono, and a **`View Cypher`**
  toggle revealing the generated query in a mono block. Showing your query to a technical
  judge buys real credibility — make it one click away, not buried.
- **Citations** under each answer as small numbered mono chips. Clicking one scrolls the
  left table to that person and flashes their row for 600ms.
- **Disambiguation is a first-class UI state, not a text message.** When
  `/api/agent/chat` returns an ambiguous resolution, render the candidates as two selectable
  cards side by side, each showing college, role and hackathon count. Clicking one sends the
  follow-up automatically. This is the moment the judge is testing — make it look
  intentional and instant.
- Suggested prompt chips above the input, always visible (they double as your demo script):
  - `Is Shiv Sharma in our database?`
  - `Find ML builders from Delhi colleges who have won something`
  - `Who has gone quiet since winning?`
  - `Who would make a good mentor this year?`
- Input: textarea, `Enter` sends, `Shift+Enter` newlines, disabled with a visible reason
  while in flight.

### Left — results table

- Reuse B1's table. Columns: Name · College · Skills · Persona · **Match reason** ·
  Engagement · checkbox.
- **Match reason** is the differentiator — a one-line factual justification per row
  (`"1 win at GenAI track, Python across 14 repos, active 3 weeks ago"`) from
  `rationale_by_user_id`. Give it the widest column.
- New rows animate in with a 120ms fade and 4px rise, staggered 20ms. Subtle. Never bounce.
- Row click → the same `ProfileDrawer` from B1.
- Multi-select with a checkbox column. When ≥1 selected, a bottom action bar slides up:
  `3 selected` · `Send invite` · `Clear`. Wire `Send invite` to a stubbed modal for now —
  C3 makes it real.
- Above the table: the active query echoed in muted text, plus `12 of 600 people`.
- Empty state before the first query is not blank: show the 4 example chips again and one
  line explaining what the Scout does.
