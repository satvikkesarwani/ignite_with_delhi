## Part 1 — Matchmaking (`backend/matchService.js`)

Three modes, all reading from `ContextProfile`, never from raw tables. That is the point:
**the matcher consumes the context layer**, which is exactly what the bonus asks for.

### `matchTeam({userId, hackathonTheme, size})`

Match on **complementary** skills, not similar ones. This is the part teams get wrong: a
cosine-similarity matcher returns four backend developers, which is a worse team.

```
score = 0.40 * role_complementarity     // fills a role the team lacks
      + 0.25 * skill_coverage_gain      // new skills added vs theme requirement
      + 0.15 * collaboration_signal     // prior TEAMMATE_OF, or shared college
      + 0.10 * reliability              // submission rate, inverse no-show rate
      + 0.10 * availability             // active, consented, not already on a team
```

Return each match with a **human-readable reason built from graph facts**, not an LLM
sentence: `"Adds ML/AI which the team lacks; 4 hackathons, 86% submission rate; teamed with
Ananya twice before"`. Also return the component breakdown so the UI can show the why.

### `matchMentor({userId})`

Match a participant's weakest evidenced skill against mentors' expertise, weighted by mentor
rating. Reason string names the gap being filled.

### `matchOpportunity({hackathonTheme, trackSponsor, limit})`

The organizer-facing one, and the best demo: *"who should we invite to the Neo4j track?"* —
rank by evidenced skill match against the track, plus engagement, plus consent. This is
directly useful to the people judging you, and it is the one to lead with.

Endpoint: `POST /api/crm/match` with `{mode, userId?, requirements?}`.

## Part 2 — Outreach (`backend/outreachService.js`)

`npm i nodemailer`.

### Transport — keep the previous plan's dual-mode idea, it is genuinely good

- **Gmail SMTP** when `GMAIL_USER` + `GMAIL_APP_PASSWORD` are set
- **Ethereal fallback** (`nodemailer.createTestAccount()`) otherwise, returning a live
  `https://ethereal.email/message/...` preview URL

Ethereal is the right default for stage: it needs no 2FA, it works on venue wifi, and
clicking through to a real rendered email is a strong visual.

### Safety — do this before anything else in this part

The 600 CSV users have **synthetic email addresses**. Sending to them bounces, and blasting
600 fake addresses from a personal Gmail can get the account flagged.

- Hard allowlist in `.env`: `OUTREACH_ALLOWLIST=you@gmail.com,teammate@gmail.com`
- Anything not on the allowlist is **forced to Ethereal**, regardless of Gmail config
- Refuse to send to `consent_flag = false`. Return a clear, visible skip reason —
  demonstrating that you respect consent is itself a point in your favour
- Cap at 25 recipients per request

### Personalization — this is where the context layer pays off

Do not merge `{{name}}` and `{{college}}` into a fixed template. That is mail-merge, and
every team will have it.

Generate the body from the person's **actual context**: their persona, their last event,
their evidenced strengths, the track that fits them.

- `hackathon-invite` — references what they built and what track suits them
- `win-back` — for dormant high-potentials: references their past win by name and date
- `mentor-invite` — for mentor-material profiles
- `custom` — organizer-authored

**Batching:** one Nemotron call per person is 25s × 10 people = unusable. Instead, generate
**one** personalized paragraph per persona group in a single batched call, then fill
person-specific facts deterministically. For the demo, precompute and cache the paragraph
per persona.

HTML template: match the app's design language — warm dark, ochre CTA, Fraunces heading.
**No purple gradient**, no emoji in the subject line.

### Record it properly

`(:Person)-[:RECEIVED]->(:OutreachEvent {template, subject, sent_at, channel, status})`.

Not a `p.status` property — a history. It matches the CSV's `crm_touchpoints`, and it lets
the agent answer *"who have we emailed twice with no reply?"*, which is a much better demo
moment than a badge changing colour. **Verify that question works in the Scout before you
finish.**

Endpoint: `POST /api/crm/outreach`.
