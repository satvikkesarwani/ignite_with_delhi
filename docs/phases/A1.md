## Build

### 1. `backend/graphSchema.js`

Constraints and indexes, idempotent (`IF NOT EXISTS`). Run before load — creating indexes
after a bulk load into Aura is much slower.

- Uniqueness on `Person.user_id`, `Hackathon.hackathon_id`, `Team.team_id`,
  `Project.project_id`, `Mentor.mentor_id`
- `Skill.name`, `College.name`, `Company.name` unique (these are the join hubs)
- Full-text index `person_search` on `Person(full_name, email, college)` — **the existence
  check depends on this**, so do not skip it
- Range indexes on `Person.last_active`, `Person.grad_year`, `Hackathon.start_date`

### 2. `scripts/load_graph.js`

Reads `data/*.csv` + `*.json`, writes the graph per `docs/CONTRACT.md`.

- **`MERGE` on business keys, never `CREATE`.** Re-running must be a no-op, not a
  duplicate. You will run this many times today.
- Batch with `UNWIND $rows AS row` — 500 rows per transaction. Row-by-row `session.run` on
  AuraDB free tier will take 20+ minutes and may time out. This matters a lot.
- Load order: `College/Skill/Company/Mentor` → `Person` → `Hackathon` → `Team` →
  `participations` → `Project` → `Result` → `MentorSession` → `Interaction` →
  `OutreachEvent`
- Every relationship gets `{source: 'csv:<filename>', observed_at: <date>}`. Provenance is a
  judged feature — wire it at load time or you will never retrofit it.
- Derive `TEAMMATE_OF` from shared team membership, with a `times` property. This powers
  matchmaking later, so compute it now.
- GitHub/LinkedIn JSON → `HAS_SKILL {source:'github', confidence:<lang pct>}`,
  `WORKED_AT`, `STUDIED_AT`
- CLI flags: `--wipe` (delete graph first, confirm prompt), `--only=<file>`,
  `--dry-run` (print counts, write nothing)
- Progress line per batch, and a final summary table of nodes and relationships created

Use the existing `neo4jService` driver — do not open a second one. Add a
`runBatch(cypher, rows)` method to `backend/neo4jService.js` if one is missing.

### 3. `scripts/verify_graph.js`

Post-load sanity, printed as a table:
- Node and relationship counts by label and type
- The 5 users with the most `ATTENDED` edges
- `MATCH (p:Person {full_name:'Shiv Sharma'}) RETURN p.user_id, p.college` → **must return
  exactly 2 rows.** This is the disambiguation trap the whole demo rests on
- Zero orphan `Project` nodes (every project has a team and a hackathon)
- Full-text index returns hits for a typo: `"Ananya Iyar"` should surface `Ananya Iyer`
