This view is the opening beat of the final demo: a judge watches a real person get added to
the platform and become a full context profile in under a minute.

## Build — `frontend/src/crm/IntakeView.jsx`

### Layout

Two columns, **not** a centered form. Left 440px: the form. Right: the live stepper, then
the resulting profile. The judge's eye goes left to right as the pipeline runs — the layout
tells the story on its own.

### Form

Full name, email, phone, college, city, primary track (select), GitHub or portfolio URL,
and a resume PDF dropzone.

- Dropzone: dashed 1px border, ochre on drag-over, shows filename and size in mono, rejects
  non-PDF and >10MB **client-side with a clear message**
- Inline validation on blur. Submit disabled with a visible reason, never a dead button
- Submit label: `Submit & build context`

### Stepper — the centerpiece

Five stages from the response's `stages[]`:
`Parse resume · Structure with Nemotron · Enrich from web & GitHub · Write to graph ·
Synthesize profile`

- Render each with a real state: pending (muted) · running (ochre, animated 2px underline)
  · done (sage check, **real elapsed ms in mono**) · failed (clay, with the reason)
- Stages 2 and 3 run concurrently on the backend — **show them as concurrent**, both lit at
  once. Do not fake a sequential waterfall; a judge who reads the timings will notice, and
  the truth is more impressive anyway.
- Under a running stage, show the actual detail the backend sends
  (`"found 14 public repos"`), not invented filler text.
- Stage 2 takes ~25s. Own it: show a live mono elapsed counter. A visible honest timer reads
  as instrumentation; a spinner reads as a hang.
- Cognee runs **after** the response as a background job. Render it below the five stages as
  a separate muted row: `Semantic memory · queued` → `indexing` → `done`, polled from
  `GET /api/crm/intake/:jobId/status`. Being visibly honest that deep indexing is async is a
  point in your favour with technical judges, not against.

### Result

On success, the right column swaps to a profile card: narrative, extracted skills with
confidence, personas, engagement, evidence count. Two buttons: `View in database →` (opens
the B1 drawer) and `Ask the Scout about them →` (navigates to B2 with the name prefilled).

If `isReturning` is true, show a sage banner: *"Existing participant — profile enriched with
new signals"*, with a before/after count of evidence items. This is the strongest possible
visual for "the context layer accumulates over time".

### Failure

If a stage fails, keep the completed stages visible, show what failed and why, and still
render whatever profile was built. A partial profile with a named missing source is a good
outcome and should look like one.
